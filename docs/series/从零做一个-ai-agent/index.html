从零做一个 AI Agent

从一次工具调用循环开始，到 MCP 协议接入、上下文预算、项目记忆、降级容错和回归评测，六章记录我做一个代码评审 Agent 的全过程。

  1. 01

    先别急着上框架：一次工具调用循环到底长什么样

    2026 年 11 月 4 日

    把 Agent 拆开看，它只是一段 while 循环：问模型、执行它点名的工具、把结果塞回去、再问。这一章写清楚这个循环的最小实现，以及我第一版漏掉的四个细节。

    约 3 分钟

  2. 02

    接 MCP 协议时踩的坑：Java SDK 和 Jackson 版本打架

    2026 年 11 月 6 日

    编译通过、打包成功、启动一切正常，第一个 MCP 请求进来就 500。NoSuchFieldError: POJO 的完整排查过程，以及这个 SDK 的 JSON 层为什么是插件化的。

    约 2 分钟

  3. 03

    上下文窗口不是无限口袋：8000 字符预算怎么切

    2026 年 11 月 8 日

    一个代码文件几千行，全塞进去模型就开始丢指令；塞太少又看不出跨文件关系。这一章写我怎么定 800 / 8000 这两个数，以及预算超了之后先砍谁。

    约 3 分钟

  4. 04

    让 Agent 记住这个项目：记忆分三层，别混成一层

    2026 年 11 月 12 日

    会话记忆、项目记忆、检索出来的证据，这三样东西混在一起是灾难。这一章写我怎么把"记住"拆开存、怎么决定什么时候写回去，以及过期规则怎么清。

    约 3 分钟

  5. 05

    工具挂了 Agent 就崩？降级、超时和两个引擎打架怎么收场

    2026 年 11 月 14 日

    评审 Agent 背后有两个引擎：C++ 静态分析服务和 Java 规则引擎。它们会超时、会给出重复结论、会互相矛盾。这一章写合并规则和三层降级，以及为什么错误信息也要写成给模型看的样子。

    约 3 分钟

  6. 06

    改了 Prompt 之后到底变好还是变差：攒一套能重复跑的用例

    2026 年 11 月 16 日

    调切片大小、改合并策略、加一条记忆规则，每次改完都觉得"看起来更好了"。这一章写我怎么用一套固定用例把这种错觉压下去，以及评测集到底该长什么样。

    约 3 分钟
