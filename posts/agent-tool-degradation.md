单机 Demo 里工具总是成功的。上线第一天就会遇到：静态分析服务没起来、请求超时、两个引擎对同一行给出不同结论。

这一章写三件具体的事：超时怎么设、两个引擎的结果怎么合、失败怎么让模型知道。

## 为什么要有两个引擎

代码评审的规则分两种，需要的实现方式完全不同：

- **单行正则类**：命名不规范、魔法数字、硬编码路径。这类规则数量多、跑得快，纯文本扫描足够
- **跨行判断类**：资源泄漏（申请了没释放）、锁的配对、分支里缺少返回。这类要维护上下文，得靠状态机

我把前者放进了 C++ 静态分析服务（顺带练手 epoll 和手写 HTTP），后者留在 Java 规则引擎。对 Agent 来说，这两者都是 `review_code` 工具背后的实现细节——但合并逻辑必须由 Agent 这层负责。

## 合并：按"规则 + 行号"去重

两个引擎都会命中同一行。直接拼接的结果是同一个问题报两遍，模型看到重复信息会当成"问题严重"，优先级全乱。

去重键用 `规则 ID + 行号`：

```text
(cpp, naming, 12)      → 保留
(java, naming, 12)     → 与上面同键，合并
```

同键冲突时的取舍规则：

1. 严重级别取高的（error > warn > info）
2. 描述取信息量大的（长度不是标准，我用的是"是否包含修复建议"）
3. 来源标记成 `cpp+java`，报告里注明两个引擎都报了

第三条很关键。后续调规则的时候，"两个引擎都报"和"只有一个报"是完全不同的信号，把来源抹掉就再也查不出来了。

排序不能只按严重级别，否则同一级别里行号乱跳，人看不下去。最终排序是 `severity desc, line asc, rule asc`。

## 超时：给工具设，不给循环设

最开始我想的是"整个评审最多 10 秒"，超了直接返回。问题是这会杀掉一个已经跑到一半、结论基本可用的流程。

正确的位置是**单个工具调用**上：

```java
// 静态分析服务，本地调用，正常 40ms 内返回
CallResult r = staticClient.review(code, Duration.ofMillis(800));
if (r.timeout()) {
    return ToolResult.partial("静态分析超时，本次只有 Java 规则结果", javaIssues);
}
```

超时值我给到 800ms，是压测出来的：正常 40ms 左右，网络抖动最差见过 300ms，800ms 已经能覆盖绝大多数抖动，再往下调会开始误杀。

关键是超时之后**不能返回空**，要返回"部分结果 + 一句话说明缺了什么"。模型拿到这句话，会在最终回答里主动补一句"本次未包含静态分析"，而不是假装什么都没发生。

## 三层降级

| 情况 | 处理 | 模型看到什么 |
|---|---|---|
| 静态服务超时 | 只用 Java 规则 | 部分结果 + 缺项说明 |
| 静态服务连接失败 | 退回本地正则兜底 | 结果 + "静态分析不可用，已用本地规则" |
| Java 规则引擎异常 | 直接报工具失败 | 错误 + 建议换个方式 |

第三条是故意不做兜底的。规则引擎挂掉说明代码有 bug，此时任何"兜底结论"都不可信，宁可让模型知道这条路走不通。

还有一层容易被忽略：**降级之后要标数据来源**。报告里每个问题都带 `source: cpp | java | local`，前端按来源上色。用户看到一片"local"，就知道该去查服务了，而不是以为代码突然变干净了。

## 错误信息是写给模型看的

这一点我改了三版才明白。第一版直接把 Java 异常 message 返回：

```text
java.net.ConnectException: Connection refused: localhost:18080
```

模型看到这行，基本只会回一句"评审服务出现错误"，然后结束。

第二版加了 hint：

```json
{
  "ok": false,
  "error": "连接静态分析服务失败（localhost:18080）",
  "hint": "该服务通常随主服务一起启动；可以改用 review_code_local 跑本地规则",
  "retryable": true
}
```

模型这次会自己换工具重试。

第三版又加了 `retryable`：可重试的错误（超时、连接失败）它才会重试，不可重试的（参数格式错）它会直接放弃并说明。不加这个字段，模型会对着一个必然失败的工具反复试到 max_steps。

## 一个反直觉的结论

做降级的过程中最大的收获不是容错代码，而是：**尽量让失败也返回结构化结果，而不是抛异常。**

异常是给程序员看的，结构化失败才是给 Agent 看的。前者中断流程，后者保留决策权。整个循环里唯一应该抛异常的地方，是参数校验失败——那种情况重试也没意义。
